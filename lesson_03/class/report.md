# Практическая работа пары 1-7

## Что надо было сделать

Создайте три консольные программы: заказ билетов, обработку серии температур и пульт учебного устройства. Используйте переменные, константы, ввод и вывод, вычисления, условия и циклы. Перед каждым контрольным запуском запишите ожидаемый результат, затем сравните его с фактическим.

### Задание 1 Заказ билетов

Программа получает имя покупателя, количество билетов, цену одного билета и признак скидки. Рассчитайте базовую сумму, размер скидки и итог к оплате. Ставка скидки равна 10% и хранится в константе. Скидка применяется ко всей базовой сумме при истинном логическом признаке.

| Данные | Тип | Условие |
| --- | --- | --- |
| Имя и фамилия | std::string | Одна строка с пробелами |
| Количество билетов | int | От 1 до 10 включительно |
| Цена одного билета | double | Больше 0 и не больше 5000 |
| Признак скидки | bool | Ввод 0 или 1 |
| Ставка скидки | const double | 0.10 |

Сначала прочитайте имя, затем все три числовых и логических поля. После успешного чтения проверьте количество и цену. При нарушении любого диапазона выведите Invalid data и завершите программу до расчёта заказа.

Базовая сумма равна цене билета, умноженной на количество. При наличии скидки её размер составляет 10% базовой суммы; при отсутствии скидки её размер равен нулю. Итог равен базовой сумме за вычетом скидки. Выведите имя, количество, базовую сумму, признак применения скидки, её размер и итог. Для печати bool словами используйте std::boolalpha в потоке вывода.

Порядок выполнения:

1. Подготовьте переменные с начальными значениями и константу ставки. Выведите приглашение и прочитайте имя целиком, затем запросите количество, цену и признак скидки.
2. Проверьте чтение и допустимые диапазоны в указанном порядке. Убедитесь, что ошибочные данные завершают программу с нужным сообщением.
3. Рассчитайте базовую сумму. Через условие определите размер скидки и сохраните итог в отдельной переменной.
4. Выведите карточку заказа с подписями. Для контрольного примера сначала вычислите каждую сумму вручную.
5. Проверьте наборы из таблицы. В отчёте укажите тип каждой переменной и объясните, почему ставка оформлена константой.

Пример консольного отображения:

```text
Name: Anna Petrova
Tickets price discount (0/1): 3 200 1
Customer: Anna Petrova
Tickets: 3
Base: 600
Discount applied: true
Discount: 60
Total: 540
```

Первые две строки содержат приглашения программы и ввод пользователя.

| Контрольные данные | Ожидаемый результат |
| --- | --- |
| 3 билета по 200, скидка 1 | База 600, скидка 60, итог 540 |
| 2 билета по 150.5, скидка 0 | База и итог 301, скидка 0 |
| 10 билетов по 5000, скидка 1 | Итог 45000, верхние границы допустимы |
| Количество 0 или 11; цена 200 | Invalid data после успешного чтения полей |
| Цена 0 или 5000.5; количество 1 | Invalid data после успешного чтения полей |
| Буква в числовом поле или признак 2 | Input error |

В каждом запуске таблицы сначала вводите имя, а затем полный набор из трёх полей. Для допустимого нижнего количества отдельно проверьте один билет.

### Задание 2 Серия температур

Программа получает количество показаний от нуля до десяти, затем читает ровно столько целых температур. Показание датчика допустимо от -50 до 100 включительно. Рабочим считается допустимое показание от 0 до 40 включительно.

Используйте for для заданного количества чтений. При температуре за диапазоном датчика увеличьте счётчик отклонённых показаний, напечатайте Rejected и перейдите к следующей итерации через continue. Для принятого значения напечатайте Accepted, увеличьте счётчик принятых показаний и добавьте температуру к сумме. Отдельно подсчитайте рабочие показания.

После цикла выведите Valid, Invalid и Working. Среднее Average рассчитывается по всем принятым показаниям. При нулевом количестве принятых значений выведите Average: n/a. Сумму храните в double, чтобы деление давало дробный результат. Температуры и счётчики имеют тип int.

Количество показаний за пределами 0–10 должно приводить к сообщению Invalid count и завершению до цикла. При ошибке чтения любого поля действует общее правило Input error; итоговые счётчики и среднее при таком завершении не выводятся.

Порядок выполнения:

1. Прочитайте количество и проверьте его диапазон. Перед циклом создайте счётчики принятых, отклонённых и рабочих показаний, а также сумму с нулевыми значениями.
2. Организуйте ровно заданное количество повторений. Внутри каждого прохода запросите и прочитайте очередную целую температуру.
3. Проверьте диапазон датчика. Для отклонённого значения измените нужный счётчик до перехода к следующей итерации.
4. Для принятого значения обновите сумму и количество. Дополнительно проверьте принадлежность рабочему интервалу.
5. После цикла выведите счётчики. Вычисляйте среднее при наличии хотя бы одного принятого показания.
6. Проверьте нулевой, обычный и граничные наборы. Сформулируйте инвариант: как число уже прочитанных показаний связано с двумя основными счётчиками.

Пример консольного отображения:

```text
Count: 3
Value: 20
Accepted
Value: 50
Accepted
Value: 101
Rejected
Valid: 2
Invalid: 1
Working: 1
Average: 35
```

Ввод количества и каждой температуры показан после соответствующего приглашения.

| Контрольные данные | Ожидаемый результат |
| --- | --- |
| Количество 0 | Все счётчики 0, Average: n/a |
| Количество 2; температуры -51 и 101 | Valid 0, Invalid 2, Working 0, Average: n/a |
| Количество 2; температуры 0 и 40 | Valid 2, Working 2, Invalid 0, Average 20 |
| Количество 2; температуры -50 и 100 | Оба приняты, Working 0, Average 25 |
| Количество -1 или 11 | Invalid count |
| Буква вместо очередной температуры | Input error, итог не печатается |

В отчёте объясните, почему температура 50 принимается датчиком и не попадает в рабочий интервал. Подтвердите, что отклонённое показание занимает одну итерацию из заданного количества.

### Задание 3 Помощник покупок по бюджету

Время — 30 минут. Создайте программу, которая помогает выбирать покупки и следит за оставшимися деньгами. Пользователь задаёт бюджет, затем по очереди вводит цены. Программа сообщает, удалось ли добавить очередную покупку, и показывает итог расходов.

Суммы в этой задаче задаются целыми рублями и хранятся в int. Начальный бюджет находится в диапазоне от 0 до 100000 включительно. За один запуск можно ввести до десяти цен. Число 0 завершает выбор. Допустимая цена покупки — от 1 до 100000 включительно.

Сначала проверьте бюджет. При выходе за его диапазон выведите Invalid budget и завершите программу до ввода цен. Для каждой цены соблюдайте порядок: успешность чтения, сигнал завершения, диапазон цены, достаточность остатка.

Если цена отрицательна или больше 100000, напечатайте Invalid price. Если допустимая цена превышает остаток, напечатайте Not enough money. При обоих отказах остаток, расходы и количество покупок сохраняются. Допустимую посильную покупку примите, напечатайте Added, уменьшите остаток и увеличьте расходы и количество покупок.

Каждая прочитанная ненулевая цена занимает один из десяти шагов, включая отклонённую. Используйте for, чтобы ограничить количество шагов, и break для завершения по нулю. После обычного выхода напечатайте Items, Spent и Remaining. При ошибке чтения действует общее правило Input error с кодом 1; итог при этом не печатается.

Порядок выполнения:

1. Создайте переменные бюджета, остатка, расходов и количества покупок. Задайте константу предельного количества цен. Прочитайте и проверьте бюджет.
2. Организуйте ввод до десяти цен. После каждого успешного чтения сначала проверьте сигнал завершения.
3. Для остальных цен последовательно проверьте диапазон и достаточность остатка. Отказ должен сохранять накопленные результаты.
4. Для принятой покупки обновите остаток, расходы и количество. Разрешите покупку, которая расходует остаток полностью.
5. Выведите итог и проверьте наборы из таблицы. Сформулируйте связь между исходным бюджетом, расходами и остатком после каждого шага.

Пример консольного отображения:

```text
Budget: 200
Price (0 stop): 70
Added
Price (0 stop): 50
Added
Price (0 stop): 100
Not enough money
Price (0 stop): 0
Items: 2
Spent: 120
Remaining: 80
```
